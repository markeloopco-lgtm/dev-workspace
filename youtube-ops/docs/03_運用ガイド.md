# 03. 運用ガイド（日々の使い方）

## 毎日の投稿フロー

### REVIEWモード（人間確認あり・推奨）

1. 「01_投稿管理」に行を追加: チャンネルキー・タイトル・動画DriveURL・サムネDriveURL・
   予約公開日時（・あれば台本）を入力
2. 10分以内に自動でAI概要欄が生成され、ステータスが「確認待ち」になる
   （すぐ欲しければメニュー「AI概要欄を生成（選択行）」）
3. AI概要欄・固定コメント案を確認し、必要なら**セルを直接編集**して手直し
4. 「承認」列にチェック → 10分以内に自動でアップロードされ「予約済み」になる
5. 予約時刻になるとYouTube側で自動公開される（GASは何もしなくてよい）

### AUTOモード（完全自動）

行を入力するだけ。生成→投稿まで自動で進みます。
概要欄を事前確認できないので、テンプレとトンマナ指示を十分に固めてから切り替えること。

### よくある投稿エラーと対処

| エラー内容 | 対処 |
|---|---|
| 予約日時は10分以上先に | 予約日時を直し、ステータスを「投稿待ち」に手で変更 |
| アップロード権限がありません | そのチャンネルのモードをFULLにした後に認証していない。「認証URLを発行」→再承認 |
| Driveファイル取得失敗 | URLが動画ファイル本体か確認。スプシ所有者のドライブに置くのが確実 |
| サムネ設定失敗（動画は成功） | チャンネルのアカウントが電話番号未確認の可能性 → youtube.com/verify で確認後、サムネはStudioから手動設定 |
| uploadLimitExceeded 等のAPIエラー | そのチャンネルの当日アップロード上限またはAPI割り当て超過。翌日に再試行 |

直したあとは**ステータスを「投稿待ち」に戻せば再試行**されます。

## 毎朝の分析の見方（5分ルーティン）

1. **00_ダッシュボード**を開く（毎朝5時台に自動更新済み）
2. 「エラー」列が0以外 → 06_エラーログを確認
3. 「要改善」列の数字が増えたチャンネル → 下段の判定付き動画一覧を見る
4. 判定の意味と打ち手:

| 判定 | 意味 | 打ち手 |
|---|---|---|
| サムネ差し替え優先 | 表示は十分あるのにクリックされていない | **最優先でサムネ変更**（タイトルも再検討） |
| サムネ改善候補 | CTRがチャンネル平均より明確に低い | サムネ/タイトルの改善候補に入れる |
| インプレッション不足 | クリック率は良いのに表示が少ない | サムネは触らない。SEO（タイトル・概要欄キーワード）や関連動画導線を強化 |
| CTR低下 | 直近7日でCTRが下がった | 表示面が変わったサイン。サムネ鮮度・競合を確認 |
| ヒット | 7日再生がチャンネル平均の2倍以上 | 同企画の横展開・次回作を検討 |
| 急上昇 | 昨日の再生が直近平均の3倍以上 | 伸びている間にコメント返信・関連動画リンク追加 |

5. 判定メモには根拠の数字が入っています（例: `CTR 2.9% / 直近10本平均 5.8% → サムネ変更推奨`）

判定基準がチャンネルの実態に合わないときは「04_チャンネル設定」のしきい値列を調整
（例: ショート中心チャンネルはCTRが構造的に低いので、CTR改善閾値を絶対値で指定する）。

## ランキング分析のやり方（02_動画分析）

フィルタ（データ → フィルタを作成）を使って:

- **CTRランキング**: CTR(%)列で降順ソート
- **再生数ランキング**: 再生(90日)で降順
- **初動ランキング**: 24h再生で降順（投稿時期が違っても比較可能）
- **7日再生ランキング**: 7日再生で降順
- **登録者獲得効率**: 登録獲得効率(/千再生)で降順 → 登録につながる企画がわかる
- **維持率**: 平均視聴率(%)で降順 → 台本・編集の質の指標
- **サムネ差し替え候補**: 判定列を「サムネ」でテキストフィルタ

## メンテナンス

- **チャンネル追加**: docs/01 の最終章のとおり（設定1行＋認証のみ）
- **一時停止**: 04_チャンネル設定の「有効」を外す（分析・投稿とも止まる）
- **全停止**: メニュー「自動実行を停止（トリガー削除）」
- **認証が切れたら**: ダッシュボードの認証列が「未認証」→「認証URLを発行」で再認証
  （OAuth同意画面が「テスト」のままだと7日で切れます。docs/01 Step 2参照）
- **実行履歴の確認**: Apps Script画面の「実行数」タブで各トリガーの成否が見られる

## 拡張の目安（20〜50chへ）

設計上そのまま増やせますが、次の順で限界が来ます:

1. **投稿本数** … 1日6本超え → 会社ごとにGCPプロジェクト分割 or 割り当て増申請（README参照）
2. **分析の実行時間** … チャンネル単位で自動分割継続するため動くが、1回の完了まで時間がかかる
   → `00_config.gs` の `DAILY_HOUR` を早朝にずらす
3. **日次ログの肥大化** … 50ch×90動画×365日で数十万行 → 集計が重くなったら
   03_日次ログをBigQuery（Googleのデータ倉庫・無料枠あり）へ移し、GASは取得と書き込みだけにする
4. さらに先は処理本体をCloud Runへ移行（シートはそのまま管理画面として残せる）
