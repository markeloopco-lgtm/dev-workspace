# YouTube多チャンネル一元管理システム（Google Sheets + GAS）

複数のYouTubeチャンネルの **投稿・分析・改善提案** を、1つのGoogleスプレッドシートで
一元管理する自動運用システムです。サーバー不要・**完全無料**（Google Apps Script +
各種API無料枠のみ）で動きます。

## できること

| 機能 | 内容 |
|---|---|
| マルチチャンネル管理 | 1つのスプシで複数ch管理。追加は「04_チャンネル設定」に1行足すだけ（まず5ch、構造上は20〜50chまで拡張可） |
| 運用モード切替 | チャンネルごとに `ANALYTICS`（分析のみ）/ `DRAFT`（分析＋AI生成）/ `FULL`（投稿まで全部）を混在可 |
| YouTube投稿 | Driveの動画URL・サムネURL・タイトル・予約日時を入力 → GASが自動アップロード＋サムネ設定＋予約公開＋結果記録 |
| AI概要欄生成 | チャンネル別テンプレ（固定部）＋ Gemini生成部（要約・CTA・ハッシュタグ・SEOキーワード・チャプター案・固定コメント案） |
| 承認フロー | AI生成後に人間が承認チェックを入れる `REVIEW` と、完全自動投稿の `AUTO` を選択可 |
| 毎日の分析 | 過去90日の動画について再生・インプレッション・サムネCTR・平均視聴時間/視聴率・総再生時間・登録者増減・高評価・コメントを毎朝自動取得 |
| 日次ログ | 毎日のスナップショットを保存し、前日比・3日/7日増加、公開後24h/3日/7日/30日の成績を計算（投稿時期が違う動画同士も比較可能） |
| 自動判定 | 低CTR→サムネ改善候補、CTR良好で再生弱→インプレッション不足、低CTR×インプ多→サムネ差し替え優先、7日再生が平均超→ヒット、CTR低下警告、急上昇検出。基準値はチャンネルごとに変更可 |
| ダッシュボード | 全chの90日再生・平均CTR・投稿本数・直近7日再生・要改善/ヒット/急上昇本数・投稿予定・エラーを一画面で表示 |
| 認証設計 | スプシ所有者とYouTube所有者が別アカウントでもOK。チャンネルごとにOAuth認証（分析専用は読み取りのみ、投稿chはアップロード権限も）。トークン類はシートに置かずスクリプトプロパティで管理 |

Slack通知は現時点では未実装です（`src/11_notify.gs` にフックだけ用意済み。将来ここに追加します）。

## シート構成

```
00_ダッシュボード   … 全チャンネルのサマリー＋要改善/ヒット動画一覧（自動生成）
01_投稿管理        … 動画URL・タイトル・予約日時を入力する投稿キュー
02_動画分析        … 全chの動画データベース（チャンネルキーでフィルタして使う）
03_日次ログ        … 毎日のスナップショット（増分・マイルストーン計算の元データ）
04_チャンネル設定   … チャンネル追加・モード・しきい値はここ
05_概要欄テンプレ   … チャンネルごとのトンマナ（固定ヘッダー/フッター/CTA/AI指示）
06_エラーログ      … 自動処理のエラー履歴
```

列の意味は [docs/02_シート仕様.md](docs/02_シート仕様.md) を参照。

## 技術構成

- **Google Sheets** … 管理画面（入力と閲覧はすべてシート上）
- **Google Apps Script (GAS)** … 自動処理本体（このリポジトリの `src/*.gs`）
- **Google Drive** … 動画・サムネイルの置き場
- **YouTube Data API v3** … 動画アップロード・サムネ設定・動画情報取得
- **YouTube Analytics API v2** … 再生・CTR・視聴維持などの分析データ
- **Gemini API**（無料枠）… 概要欄などのAI生成
- 将来大規模化したら: 日次ログをBigQueryへ、処理をCloud Runへ移行（docs/03の「拡張」参照）

## セットアップ（概要）

詳細手順は **[docs/01_初期セットアップ.md](docs/01_初期セットアップ.md)**。大まかには:

1. Google Cloudで無料のプロジェクトを作り、YouTube Data API / YouTube Analytics API を有効化、OAuthクライアントを作成
2. 新規スプレッドシートの Apps Script に `src/` のファイルと `appsscript.json` を入れる（OAuth2ライブラリも追加）
3. スクリプトプロパティに `OAUTH_CLIENT_ID` / `OAUTH_CLIENT_SECRET` / `GEMINI_API_KEY` を設定
4. メニュー「📺 YouTube管理 → ① 初期セットアップ」→ チャンネルを登録 → 「認証URLを発行」→ 各チャンネル所有者に承認してもらう
5. 「② トリガー設定」で毎日の自動実行を開始

## 既知の制限・注意

- **アップロードのAPIコスト**: YouTube Data APIの無料枠は1日10,000ユニット、動画1本の投稿は約1,600ユニット。**1つのGCPプロジェクトで1日約6本まで**。超える運用になったら会社ごとにGCPプロジェクトを分けるか、割り当て増申請をする
- **サムネ設定**は、チャンネルのアカウントが「電話番号確認済み」でないとAPIが拒否する（失敗しても動画投稿自体は成功扱いで、エラー内容欄にメモが残る）
- **Analytics データは約2日遅れ**で確定する（YouTube側の仕様）。当日・前日の数字は暫定値
- **サムネのインプレッション/CTR**は2026年1月にAPI公開されたメトリクス（`videoThumbnailImpressions` 等）を使用。取得できない環境ではCTR列が空欄になり、CTR系の判定は自動でスキップされる（06_エラーログに1回だけ記録）
- GASの**6分実行制限**は、チャンネル単位・アップロードのチャンク単位で進捗保存→1分後に自動再開する仕組みで回避済み
- 動画ファイルはスプレッドシート所有者のDriveから読む（Driveの「リンクを知っている全員」共有は不要。所有者のマイドライブに置くのが確実）
