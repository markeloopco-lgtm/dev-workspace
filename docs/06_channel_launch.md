# 06. YouTubeチャンネル開設・運用開始

docs/01〜05 でモデルと配信システムを作る。このドキュメントは
**「配信する場所（チャンネル）そのもの」を作る**ための手順書。

順番としては、モデルが完成する前でも並行して進められる。
むしろ**ライブ配信の有効化には最大24時間かかる**ので、早めに済ませておくとよい。

---

## Step 0: チャンネルの中身を決める（開設より先）

チャンネル名・アイコン・キャラ設定は後から変えると視聴者が離れる。
最初に紙に書いて固めてから開設する。

| 項目 | 決めること | 記入欄 |
|---|---|---|
| チャンネル名 | 検索されやすく、読み方が一意なもの | |
| ハンドル（@〜） | 半角英数。後で変更可だが実質固定と考える | |
| キャラ名 | チャンネル名と同じでもよい | |
| キャラの一人称・口調 | AITuberKitのシステムプロンプトにそのまま書く | |
| 得意な話題 | 3つに絞る（雑談だけだと会話が続かない） | |
| やらない話題 | 政治・宗教・特定個人の話など。プロンプトで禁止する | |
| 配信の型 | 「雑談放置配信」「作業配信」「ゲーム実況」など | |
| 配信頻度 | 週◯回・◯時から。放置運用でも固定枠のほうが伸びる | |

**キャラ設定はそのままAITuberKitのシステムプロンプトになる**ので、
決まったら `configs/` にメモしておくと使い回せる。

### 参考チャンネルを真似る場合

真似たいチャンネルがあるなら、開設前に次を書き出しておく。
これがそのままキャラ設定とサムネ方針になる。

- チャンネル名の付け方（キャラ名だけ / キャラ名＋肩書き / 単語系）
- アイコン・バナーの絵柄（この絵柄が docs/01 の一枚絵の発注仕様に直結する）
- 動画・配信のタイトルの型（例: 「【雑談】〜」「#12 〜」など）
- 1本あたりの長さと投稿頻度
- 概要欄に何を書いているか（自己紹介・SNSリンク・使用素材のクレジット）
- コメントとの絡み方（読み上げ中心 / 話題を振る / スパチャ読み）

## Step 1: チャンネルを開設する

**ブランドアカウントで作ること。** Googleアカウント名（本名）と切り離せて、
後から管理者を追加できる。個人アカウント直下で作ると名前の分離ができない。

1. 配信用のGoogleアカウントを用意する（普段使いと分けるのを推奨）
2. YouTubeにログイン → 右上アイコン → 「設定」
3. 「チャンネルを追加または管理する」→「チャンネルを作成」
4. チャンネル名を入力して作成（＝ブランドアカウントのチャンネルができる）
5. 「チャンネルをカスタマイズ」から以下を設定
   - **ハンドル**（@〜）
   - **プロフィール写真**: 800×800px 推奨、2MB以下
   - **バナー画像**: 2048×1152px 推奨、6MB以下。中央 1235×338px は
     どのデバイスでも必ず表示される安全領域
   - **説明（概要欄）**: キャラ紹介＋配信頻度＋クレジット表記（Step 5参照）

アイコン・バナーは docs/01 で用意する一枚絵から切り出して作れる。

---

## Step 2: ライブ配信を有効にする（最大24時間かかる）

1. YouTube Studio → 左メニュー「ライブ配信」（または右上のカメラ＋アイコン）
2. **電話番号による確認**を求められるので済ませる
3. 初回は有効化まで**最大24時間**待つ

有効化の条件（2026年8月時点。画面の表示が最新なのでそちらを優先すること）:

| 条件 | 内容 |
|---|---|
| 電話番号の確認 | 必須 |
| 過去90日間のライブ配信制限 | 無いこと |
| 初回の待ち時間 | 最大24時間 |
| **PC（エンコーダ）配信** | **登録者数の条件なし** ← 本構成はこちら |
| モバイル配信 | 登録者50人以上が必要 |

本構成は**OBSからのエンコーダ配信**なので、登録者0人でも配信できる。
「登録者◯人ないと配信できない」はスマホ配信の話。

---

## Step 3: APIキーを取得する

配信システム側で必要になるキーは2つ。どちらも無料枠がある。

| キー | 用途 | 取得先 | .envの変数名 |
|---|---|---|---|
| Gemini APIキー | キャラの応答生成 | Google AI Studio | `GOOGLE_API_KEY` |
| YouTube Data API v3 キー | コメント取得 | Google Cloud Console でAPIを有効化して発行 | `NEXT_PUBLIC_YOUTUBE_API_KEY` |

詳細な設定は docs/04 の Step 4・Step 5 を参照。

> **注意**: APIキーはパスワードと同じ。`.env` に書き、
> **絶対にGitにコミットしない・配信画面に映さない**。
> `.gitignore` で `.env` は除外済み。

---

## Step 4: 初配信までのチェックリスト

- [ ] チャンネル開設・アイコン・バナー・概要欄を設定した
- [ ] ライブ配信の有効化が完了した（24時間経過後に画面で確認）
- [ ] Live2Dモデルが `public/live2d/<名前>/` に入って動いている（docs/03・04）
- [ ] Style-Bert-VITS2が起動して声が出る（docs/04 Step 3）
- [ ] Geminiで応答が返る（docs/04 Step 4）
- [ ] OBSでクロマキー合成できている（docs/04 Step 6）
- [ ] **限定公開でテスト配信**して、映像・音声・コメント応答を通しで確認した
- [ ] 概要欄にクレジット表記を入れた（Step 5）
- [ ] 配信タイトル・サムネ・待機画面を用意した

**いきなり公開配信しないこと。** まず「限定公開」で配信を立てて、
別の端末から自分でコメントして応答が返るかを必ず確認する。
コメント取得には配信の動画IDが必要（docs/04 Step 5）。

---

## Step 5: 概要欄に書くクレジット表記

docs/04 のライセンス表に対応する表記。使ったものだけ書けばよい。

```
■ 使用素材・ツール
音声合成: Style-Bert-VITS2
音声モデル: （使用したモデル名とその指定クレジット）
アバター: Live2D Cubism
配信システム: AITuberKit
```

- 同梱音声モデルは**クレジット表記が必須のものがある**（あみたろ系など）。
  使うモデルの規約を確認して、指定された文言をそのまま書く
- JVNVコーパス由来のモデルは CC BY-SA 4.0

## Step 6: 収益化を考える場合の注意（重要）

**本構成は現時点では非商用前提。** 収益化する前に必ず確認すること。

1. **AITuberKitのLive2D機能は商用利用不可**（Live2D社との契約上の制約）。
   収益化＝商用にあたるため、Live2Dのまま収益化はできない。
   → VRM/PNGTuberモードに切り替えるか、最新のライセンス状況を確認する
2. **AITuberKit本体**も商用は別途商用ライセンスが必要
3. **Cubism Editor**の出版許諾契約（docs/03参照）

順序としては「非商用で配信を始める → 伸びてきたタイミングで
各ライセンスの商用条件を確認・相談する」を推奨。詳細は docs/04 のライセンス表。

### AI生成コンテンツの扱い

- YouTubeには**合成コンテンツの開示**ルールがある。アニメ調のアバターは
  「実在の人物・出来事と誤認させるリアルな合成」ではないので通常は対象外だが、
  アップロード画面の該当設問には正直に答える
- **同じ内容の大量生産は「使い回し・非本物のコンテンツ」として扱われうる**。
  量産パイプラインを使う場合でも、1本ごとに内容の差をつけること
- 規約は変わる。**投稿画面とYouTubeヘルプの最新表示を優先する**

## つまずいたら

| 症状 | 確認すること |
|---|---|
| 「ライブ配信」が押せない | 電話番号確認済みか／24時間経過したか／過去90日の制限 |
| コメントを拾わない | 配信の動画IDが設定されているか／YouTubeモードON／APIキー |
| コメントに反応しない時がある | 仕様。1サイクルにつきランダムに1件だけ返す（docs/04 Step 5） |
| 声が出ない | Style-Bert-VITS2サーバーが起動しているか（別ウィンドウで動かす） |
| 背景が緑のまま映る | OBSのクロマキーフィルタが適用されているか |
| APIクォータ超過 | ポーリング間隔を延ばす（3〜30秒で調整可）／会話継続モードをOFF |
