# チャンネルの作風分析プロンプト（Claude Codeに渡す・PCで実行）

参考チャンネルの動画をフレーム単位で分析し、**台本を入れれば同じ作風の動画が作れる**ための
目標値（数値）・構成の型・見せ方の仕様をそろえる。YouTubeにつながるPCで実行する
（クラウド環境はネットワーク設定でYouTubeに接続できないことがある）。

```
prompts/channel_style_analysis.md を読んで、チャンネル https://www.youtube.com/@チャンネル名 を
「名前: xxx」として分析してください。1ステップずつ確認しながら進めてください。
```

---

## あなた（Claude）への指示

ユーザーは非エンジニア。各ステップの前に何をするか一言伝え、ユーザーの判断が要る所（動画の取得など）は
必ず確認を取る。コマンドは `.venv-video\Scripts\python.exe scripts\vlab.py ...` の形で実行する。
以下の `<名前>` はユーザーが決めた英小文字の名前（例 `zunda_matsuro`）。

### Step 1: 準備

1. このリポジトリのブランチ `claude/video-frame-analysis-cyhxvk` を取り込む（未クローンならクローン）
2. docs/06_video_analysis.md の Step 1（ffmpeg・`.venv-video`・`requirements-video.txt`）→ `vlab doctor`

### Step 2: 分析する動画を選ぶ

1. 動画の一覧だけを取る（ダウンロードはしない）:
   `.venv-video\Scripts\python.exe -m yt_dlp --flat-playlist --print "%(id)s %(duration_string)s %(title)s" "https://www.youtube.com/@チャンネル名/videos"`
2. **単発の通常回を3〜5本**選んでユーザーに確認する。総集編・まとめ・ショート・生配信は作風が違うので除く。
   新しい回を中心に、尺が近いものをそろえる

### Step 3: フレーム単位の計測

1. 取得は規約上の注意があるので、docs/06_video_analysis.md「⚠ 先に読む」の要点をユーザーに伝え、
   本人が了承した場合だけ1本ずつ `vlab fetch "https://www.youtube.com/watch?v=動画ID"` を実行する
   （Geminiのキーがあれば先に `vlab watch` で構成をつかむのもよい）
2. 各動画を `vlab analyze refs\動画ID.mp4` で解析する
3. 見せ方を確かめたい瞬間（話者が替わる所・字幕が出る所・場面が替わる所）は
   `vlab frames` で連続フレームの一覧画像を作って見る
   （画像を見るとAnthropicに送信されることをユーザーに伝える）
4. 補助として `scripts\analyze_video.py analyze refs\動画ID.mp4` の簡易レポート
   （shots.csv・素材ごとの色のばらつき・BGMの推定）も見てよい

### Step 4: 目標値・構成の型・見せ方の仕様を書く

1. 数値: `vlab aggregate analysis\ID1 analysis\ID2 ... -o configs\style_<名前>.yaml`
   （`configs/style_profile.yaml` は上書きしない。制作時は台本の `style: configs/style_<名前>.yaml` か `--style` で指定）
2. 構成の型: prompts/structure_analysis.md の手順。まとめは `configs/structure_<名前>.md` に書く
3. 見せ方の仕様: 下の「見せ方の仕様の書き方」に沿って、まず各動画の `analysis\動画ID\style_spec.md`、
   最後に共通点を `configs/style_spec_<名前>.md` にまとめる

### Step 5: 再現に足りないものを洗い出して報告する

`configs/style_spec_<名前>.md` の最後の対応表をもとに、ユーザーへ次の3つを報告する:

- いまの videolab（episodes/README.md の書式）で再現できること
- 機能が足りないこと（例: 立ち絵の口パク・表情の切り替え）と、その作り方の案
- ユーザーが用意する素材（立ち絵・BGM・効果音・背景）と、入手先の候補と利用条件

**機能の追加はユーザーの了承を得てから**。了承されたら、追加する前に作業計画を見せる。

### Step 6: 保存と後片付け

1. コミットしてよいのは `configs/style_<名前>.yaml`・`configs/structure_<名前>.md`・
   `configs/style_spec_<名前>.md` だけ（数値と抽象化した記述）。`refs/` と `analysis/` は入れない（.gitignore済み）
2. ブランチ `claude/video-frame-analysis-cyhxvk` にプッシュする（クラウドのセッションからも続きができるように）
3. 研究が済んだら docs/06_video_analysis.md の Step 7（purge）で参考動画の複製を消す

## 見せ方の仕様の書き方（style_spec.md）

数値で測れない「見せ方」を、真似できる粒度で書く。時刻は `mm:ss`、大きさ・位置は画面比（%）で書く。

1. **画面構成**: 登場キャラの人数、立ち絵の位置（左下・右下など）と大きさ（画面の高さ比）、
   背景の種類（イラスト・写真・フリー素材・単色）と切り替わる頻度、挿絵・図解の出し方
2. **立ち絵の動き**: 口パク（何コマごとに開閉するか・声の大きさに連動か）、まばたき、
   表情の切り替え（台詞ごとか、感情の山だけか）、揺れ・跳ね・拡大などの演出、話していないキャラの扱い
3. **字幕（テロップ）**: 位置、1行の文字数と行数、フォントの系統（丸ゴシック・極太ゴシックなど）、
   文字色・縁取り（色・太さ・二重縁）、話者ごとの色分け、背景の帯（座布団）の有無と形、
   出し方（パッと切り替え・フェード）、話者名の表示
4. **場面の転換**: 章タイトル・アイキャッチ・暗転の有無、場面ごとの背景の切り替え
5. **音**: 声（VOICEVOXのどの話者・スタイルに近いか、話速、抑揚）、BGM（曲調・声との音量差・場面での切り替え）、
   効果音（頻度・種類・どんな台詞で鳴るか）
6. **冒頭と締め**: タイトルの出し方、オープニング、締めの定型
7. **再現の対応表**: 1〜6の各項目について「videolab の設定でできる（どのキー）／機能が足りない／素材が要る」

### 守ること

- 台詞・ナレーションの**引用は10文字以内**に留め、基本は要約で書く（型の抽出であって台本の複製ではない）
- 参考動画の画像・音声・フレームを `configs/` やコミットに入れない
- **キャラクターの絵を作らない・似せて生成しない**。ずんだもん等のキャラクターは、公式の利用ガイドラインに沿って
  配布されている立ち絵素材をユーザーが入手して使う前提で、「必要な素材の種類」（表情差分の数・口の開閉・
  まばたきの差分）だけを書く。声は VOICEVOX の利用規約に沿い、クレジット（例「VOICEVOX:ずんだもん」）を必ず入れる
- チャンネル固有の名前・ロゴ・決め台詞・シリーズ名は再現の対象にしない（学ぶのはテンポと見せ方の品質）
- YouTubeの収益化ポリシー（繰り返しの多いコンテンツ）を踏まえ、テンプレの量産ではなく毎回の独自の内容を前提に書く
